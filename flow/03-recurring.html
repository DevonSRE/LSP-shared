Recurring billing — auto-renewal, retries and grace

A court switches on auto-renewal once, then a daily job charges its saved card. JudicAI asks Paystack what happened to each charge (there is no webhook), and an hourly job settles any that were still processing. Auto-renewal needs a saved card, so it only applies to courts that have paid by card. Every box shows the endpoint it calls (base path /api/v1).

Things worth knowing

  • A court that only ever pays by bank transfer has no saved card, so it can't use auto-renew. It stays on manual renewal and pays each cycle through checkout.
  • Turning on auto-renew never charges the court. It only reuses a card saved from an earlier payment, so a court has to pay once by hand first.
  • There is no webhook: this app shares its Paystack account with others, so it cannot count on being told anything. The reply to the charge call is deliberately ignored; the outcome comes from asking Paystack (verify) about that charge, straight away and again hourly if it was still processing. The reconcile job runs before the daily dunning job, so a court that has paid is never moved to grace.
  • Retries stop once the configured attempts are used (default 3) and the subscription stays in GRACE until grace runs out.
  • What happens after a failed charge is covered by the dunning and suspension flow: grace, retries (the limit is set by the admin, default 3), and suspension.
  • A charge Paystack never saw (for example a network failure sending it) is not a declined card, so it is closed without counting against the court. The next daily run tries again.
