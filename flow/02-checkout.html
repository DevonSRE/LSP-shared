Subscription checkout — pay once per cycle

A court picks a plan, pays on Paystack, and is confirmed on return. Every box shows the endpoint it calls (base path /api/v1). The backend starts the Paystack transaction itself and never trusts an amount or plan sent back from the browser.

Things worth knowing

  • Verify is safe to call twice. A second call for a reference that's already paid returns the current subscription and changes nothing.
  • Renewing early adds a cycle on top of the existing end date, so no paid time is lost.
  • Every successful payment quietly stores a reusable card when Paystack provides one. That's what later lets the court switch on auto-renew — see the recurring billing flow.
  • A non-published plan can only be checked out by a court that's already on that exact plan (renewal). See the plans workflow.
